# Security audit remediation — 17 October 2026

This addresses the user-supplied static audit against the current code. Findings were checked against actual code and test behavior. A static concern is not evidence of a successful attack or compromised customer data.

| Audit item              | Changes and evidence                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| ----------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| MongoDB query objects   | Runtime primitive-string checks at workspace records, Mongo job operations and owned document boundaries. Reject objects, arrays, empty identifiers and control characters before querying. Validate immutable job identity and record identity on mutations. Invalid parameters return 400 through the shared handler. Operator-object regression cases cover the reported `$ne`/`$gt` patterns. Existing authenticated ownership checks remain necessary. The supplied audit did not demonstrate a reachable account bypass from a specific endpoint.                                                                                                          |
| CSRF origin fallback    | Unsafe methods require a trusted Origin or Referer; missing, malformed, `null` and cross-site origins are denied. Only the exact Razorpay webhook path may omit origin without cookies, and its raw-body HMAC verification remains mandatory. An infrastructure proxy secret does not bypass browser-origin checks. Request fixtures now supply the same origins browsers send.                                                                                                                                                                                                                                                                                  |
| Logout cookie           | Expiry uses the same HttpOnly, SameSite, path and HTTPS/production Secure policy as issuance. Server-side session deletion remains authoritative. The original omission was inconsistent hardening; absence of Secure on an HTTPS deletion alone did not establish the claimed browser failure.                                                                                                                                                                                                                                                                                                                                                                  |
| CSP                     | Middleware generates an unpredictable nonce per HTML response, replaces incoming nonce/policy headers, forwards the policy for Next hydration and emits it on the response. Root rendering reads request headers so nonce-bearing HTML is dynamic and private/no-store. Production script policy has no unsafe-inline/eval, and event-handler attributes are denied. Connect, media, frame and image policies use explicit origins instead of unrestricted HTTPS/WSS. Sandbox print pagination receives the parent nonce. Browser tests inject parser-origin scripts/event handlers and verify they are blocked while auth and print preview remain interactive. |
| Notes HTML sink         | The typed renderer already escapes text and uses untrusted KaTeX with expansion limits; no working XSS bypass was established. Added DOMPurify at the browser HTML sink as defense in depth, retaining sanitized HTML/MathML/SVG for KaTeX while prohibiting active embedding/form tags. Attack strings and safe radical rendering are covered.                                                                                                                                                                                                                                                                                                                  |
| PDF resource exhaustion | Both PDF upload entry points use a separate child process, rather than parsing within the HTTP event loop. Heap cap 128 MB, default one child per API process (configurable maximum two), 45-second deadline (hard maximum 90), cancellation/termination, 10 MB input, 500 pages and 3 million extracted characters. Parser errors expose a safe message. This also contains native parser crashes better than worker threads; a Windows thread-based attempt failed during testing and was replaced. Capacity saturation returns 503. This is bounded processing, not a durable PDF job queue or a full OS sandbox.                                             |
| Proxy IP identity       | Vercel ingress is copied into a private header which the frontend always overwrites. The backend accepts it only with the authenticated proxy envelope and validates it with `net.isIP`. Generic custom proxies use a configured number of hops from the right; never blindly select a caller's leftmost entry. A backend without a verifiable anonymous ingress returns retryable 503 instead of consuming a shared anonymous bucket. Account rate buckets still require verified sessions.                                                                                                                                                                     |
| Health disclosure       | Public API and worker health return only `{ok: boolean}`, with appropriate HTTP status. Database checks still run internally. Deployment smoke checks now assert the minimal contract; backend Git revision/topology is no longer exposed there. Operational detail remains in the existing MFA-protected admin overview.                                                                                                                                                                                                                                                                                                                                        |

## Compatibility and deployment

Nonce-based Next rendering intentionally changes HTML from static caching to request rendering. This costs more server work and should be included in Vercel capacity monitoring; API and generation queues still run on the configured backend. Responses and RSC navigation must never reuse another response's nonce through a custom CDN. Sitemaps/robots remain independent routes.

PDF process limits bound V8 heap and application work; native allocation and total container memory still require hosting limits and monitoring. The child receives only minimal runtime environment values, not database/API credentials. `PDF_MAX_CONCURRENT=1` is the default for small hosts. Worker generation/video jobs retain their existing durable queue. On a sleeping/free host, cold starts and capacity limits remain operational constraints.

`TRUSTED_PROXY_HOPS` applies only to a custom, access-restricted ingress that appends the documented number of hops. The normal Vercel-to-Render deployment uses its authenticated private header instead. Do not enable generic proxy trust on a publicly bypassable server.

No paid hosting changes, database purges, real payment charges, intrusive live attack tests or credential changes were made. The user's Chart/Table/Metadata CSV files remain untouched. These controls do not establish immunity to every attack; patch runtimes, monitor failures and maintain tested backups.
